# 台股量化策略研究彙整

> 這份文件彙整「用真實資料尋找正 EV、風險調整後報酬夠好的台股交易策略」
> 這條研究線目前為止的所有結果——包含成功、失敗、被否證的假設，誠實記錄，
> 不只放好看的數字。每一項結論都是實際跑在 Neon Postgres 真實資料（透過
> FinMind 每日累積、經 GitHub Actions 執行回測）上的結果，不是模擬或預測。

最後更新：2026-09-18（同日跳空回補策略驗證完成）

---

## 1. 資料與方法論

- **資料來源**：FinMind API → 每日 GitHub Actions 排程 → Neon Postgres。
  截至本次回測，資料庫已累積 **150 檔股票、2023-09-18 ~ 2026-09-17**（約 3 年）
  的日線 OHLCV。
- **為什麼所有分析都在 GitHub Actions 跑**：沙盒本身連不到 FinMind / Neon，
  所有「真實資料」的結果都是先寫腳本、commit、觸發 workflow、讀 GitHub
  Actions 的 job log 才拿到的——**絕不在讀到真實 log 之前預測或編造結果**。
- **反未來函數紀律**：所有訊號一律只用 T-1（含）以前已知的資料
  （`indicators.shift_by_group`），例外只有「訊號當天（T 日）自己的收盤價/
  成交量」這種在 T 日收盤後就已知、當天判斷當天用的特徵，符合
  `tw_quant/signals.py` 既有慣例。
- **交易成本**：全程套用 `tw_quant/costs.py` 的完整成本模型（證交稅、手續費、
  跳動點滑價），沒有任何「毛報酬」數字被當成能用的結果。
- **統計驗證方法**：
  - **Rank IC**：訊號與 forward 報酬做橫斷面 Spearman 等級相關，逐日算、
    取平均，t 值 = mean_IC / (std_IC / sqrt(n))（注意：沒做 Newey-West
    修正，重疊窗口的自相關會讓 t 值某種程度上偏高估）。
  - **高原 vs 尖峰檢查**：任何好看的單一回測數字，一定會在鄰近參數值上
    重跑，確認結果是「平滑高原」還是「一碰就崩的懸崖」——後者視為過擬合
    /巧合，不採用。C+D 混合策略的 Sharpe 0.60 就是這樣被抓到是假訊號的
    （見第 4.5 節）。
  - **EV / 勝率 / 風報比 / PF 的正確記帳**：backtest 結束時還沒平倉的部位，
    一定要用最後收盤價「虛擬平倉」後併入統計，否則會系統性低估 EV/勝率
    （贏家部位通常留倉最久，排除它們等於只看「已經出場的輸家」）。這個
    邏輯統一寫在 `tw_quant/backtest_stats.py`。

## 3. 目前最佳單一策略：結構轉折 C（Market Structure Shift + 量能確認）

這是整個研究過程中找到的**最站得住腳的候選策略**，多次重跑結果一致：

**訊號邏輯**：
- 魚池：流動性門檻 + 站上 60 日均線多頭排列（`signals.build_pool_mask`）
- 下跌情境確認：過去 20 日低點持續創新低（`dt_win=20`）
- 結構突破：收盤價突破過去 15 日高點（`swing_window=15`）
- 量能確認：成交量 > 20 日均量 × 1.3 倍（`volume_confirm_mult=1.3`）
- 出場：2.5×ATR 吊燈停利（`atr_multiplier=2.5`, `chandelier_lookback=10`）
- 大盤環境門檻放寬：`breadth_threshold=0.25`、`volume_ratio_threshold=0.9`
- 全域風控：產業曝險上限放寬到 30%（`max_industry_exposure_pct=0.30`）

**績效（約 3 年、完整交易成本）**：

| 指標 | 數值 |
|---|---|
| 總報酬 | 11.37% |
| CAGR | 3.79% |
| MDD | 11.69% |
| **Sharpe** | **0.43** |
| Calmar | 0.32 |
| 交易筆數 | 42 |
| 勝率 | 31.0% |
| EV%（勝率加權） | 1.53% |
| 獲利因子 PF | 1.36 |

**誠實評估**：使用者要求「持續探討直到 Sharpe 及格的 1.0」，但在系統性測試
過參數調整、風控放寬、訊號混合（共用資金池與獨立資金 sleeve 兩種方式都
試過）之後，沒有找到任何能穩健推高 Sharpe 到 1.0 的槓桿。已明確告知使用者：
在只有 3 年單一區間、沒有真正樣本外驗證的情況下，Sharpe 1.0 可能是不切實際
的目標。

## 4. 被否證/失敗的方向（誠實記錄）

### 4.1 短期反轉策略
IC 掃描顯示短期反轉有統計上顯著的訊號，但做成真正逐日調倉策略、套用完整
成本後，報酬轉負——訊號強度不足以覆蓋台股約 0.6% 的來回交易成本。

### 4.2 C + D（結構轉折 + 均值回歸）共用資金池混合
表面上 Sharpe 從 0.43 提升到 0.60，但做「高原 vs 尖峰」穩健性檢查時，
只要微調 D 策略的 `near_low_win` 參數（5→10→15→20），Sharpe 就從
0.60 崩到 0.13→-0.40→-0.91——是**懸崖不是高原**，判定為共用風控鎖耦合出
的過擬合假訊號，不是真正的分散化效果。

### 4.3 C + D 獨立資金 sleeve 混合
改用獨立資金池（不共用全域風控鎖，兩條權益曲線事後相加）重測，結果變得
平滑（不再是斷崖），但依然全面劣於 C 單獨使用（最佳組合 Sharpe 0.23，
仍低於 C 的 0.43）。

### 4.4 C + E（結構轉折 + 因子動能）跨引擎混合
與 C 單獨使用在統計上無法區分（0.42 vs 0.43）。

**結論**：分散化只有在兩條腿「各自夠強、且真正低相關」時才有效，光是
「低相關」本身不足以帶來穩健的 Sharpe 提升。

### 4.5 長假風控疊加層
假設：長假前最後一天的前一交易日收盤強制平倉，能不能降低風險、改善
風險調整後報酬？結果：MDD 確實從 11.69% 降到 9.46%，但總報酬從 11.37%
崩到只剩 0.71%（傷得更重），Sharpe/Calmar 雙雙惡化（0.43→0.07、
0.32→0.03）。診斷：這是個對 42 筆已精心篩選過的交易硬套的粗糙規則，
很可能打斷了好幾筆策略本身最好的趨勢延續型獲利單，母體層級的日曆效應
不會等比例轉移到這個特定的交易選股上。

### 4.6 延遲一天可執行版跳空訊號
背景：「T 日開盤跳空 → T 日盤中報酬」IC 高達 mean=-0.25、t=-54.82，是
全專案最強的統計規律，但原本的逐日引擎架構（T 日收盤算訊號、T+1 日開盤
才進場）天生無法交易「同一天」的效應。這裡改測「延遲一天」的可執行版：
用 T 日收盤已知的跳空幅度/盤中報酬當訊號，T+1 日開盤進場。IC 掃描顯示
延遲後訊號依然統計顯著（`intraday_ret` t=-4.9~-7.7，`gap_pct` t=-1.45~
-3.75），但套用完整成本後跑過的 36 組組合全部淨負（最佳 Sharpe 只有
-0.02，全部 PF < 1）——延遲一天後訊號還在，但強度已經扛不住交易成本，
跟 4.1 的短期反轉是同一種失敗模式。

## 5. 同日「開盤買、收盤賣」跳空回補策略（本次新增，唯一被驗證有效的邊際策略）

### 5.1 動機與架構突破

4.6 節確認了「同一天內」的跳空回補效應無法在延遲一天的架構裡使用。
使用者指出一個關鍵修正：日線 OHLC 本身就同時記錄了「當天開盤價」與
「當天收盤價」——不需要分鐘/tick 級盤中資料，只要是「T 日開盤觀察到
跳空、T 日收盤前決定出不出場」這種只用頭尾兩個價位的策略，用現有日線
資料就能正確回測。這個修正是對的，於是新建了專門的**當沖回測引擎**
`tw_quant/intraday_roundtrip.py`：T 日開盤看到跳空幅度夠大就買進、T 日
收盤全部平倉，訊號與執行都在同一天內完成，不依賴任何未來資訊。

**誠實揭露的三個限制**（寫在該檔案檔頭）：
1. 沒有台股現股當沖資格清單（信用交易資格、注意股/處置股排除等），
   假設候選股都能當沖，實際可交易標的可能比回測顯示的少。
2. 進場價用當天開盤價，假設能在開盤時或極短時間內成交，沒有額外開盤
   滑價（沿用系統慣例：進場只收手續費、不額外算滑價）。
3. 證交稅沿用系統一貫的標準 0.3% 賣出稅率，沒有假設當沖優惠稅率
   （歷史上台灣曾階段性調降當沖證交稅到 0.15%，但現況未確認，保守不
   假設適用——如果實際稅率更低，真實報酬會比這裡回測出來的更好）。

### 5.2 開發過程的插曲：一個看似是 dtype bug、實際是資金配置 bug

引擎第一版用 `.replace([inf, -inf], pd.NA)` 處理跳空幅度的除以零情況，
這會把 float64 欄位隱性升級成 object dtype，破壞後續數值篩選——已修正為
`np.nan`。但修正後測試仍然失敗（`top_n=1` 情境下永遠 0 筆交易），逐層
加印診斷後找到真正原因：**`top_n=1` 會讓 `per_stock_budget` 等於 100%
資金**，用整股（lot）無條件捨去後幾乎不留現金餘裕支付手續費，於是唯一
的候選交易被「現金不足」規則正確地拒絕了——這不是 bug，是這個極端測試
情境（把 100% 資金押一檔股票、零緩衝）觸發到的合理行為，跟
`factor_backtest.py` 既有的資金配置慣例一致。真實回測的 `top_n` 通常是
15~30，每檔只佔一小部分資金，lot 捨去自然會留下餘裕，不會遇到這個問題。
最終修法：測試裡小幅加碼可用資金留手續費緩衝，不動生產程式碼邏輯。

25 組裡只有 8 組（32%）總報酬為正，全部集中在 **gap 門檻 ≥ 5%**，且
**7% 門檻下 top_n=5/10/15/20/30 全部同時為正**，Sharpe 平滑從 0.27 升到
0.51——這是一個真正的高原，不是單點僥倖。門檻一旦降到 3% 以下，交易
成本（來回約 0.6%）就吃掉大部分甚至全部回補幅度，變成穩定虧損，跟 4.1/4.6
節的失敗模式相同。

**誠實評估**：假設成立——大跳空（≥7%）確實有正 EV 的同日回補效應，且
禁得起高原穩健性檢查。但代價是樣本天生稀少（3 年僅 42~54 筆交易）、
賺得薄（最佳組合 3 年總報酬僅 1.45~2.71%，CAGR 不到 1%），Sharpe/Calmar
好看很大一部分是因為分母（波動度）也極小，不是因為賺得多。**不建議單獨
使用**，比較有意義的下一步是把它當成小規模獨立資金 sleeve 疊加到策略 C
上（尚未測試）。

## 6. 其他重要發現

### 6.1 全專案最強統計規律：隔夜跳空 → 當日盤中報酬
`analyze_calendar_effects_from_db.py` 發現「T 日開盤跳空幅度」與「T 日
盤中報酬（收盤 vs 開盤）」呈現極強負相關：**mean IC = -0.25，t = -54.82
（n=728 天）**，是整個探索過程效應量最大、統計上最穩健的規律。第 5 節的
同日回補引擎就是為了把這個訊號變成可執行策略而建的。

### 6.2 FinMind 盤中資料現況
確認 FinMind 有提供分鐘級/tick 級歷史資料（`TaiwanStockPriceTick`、
`TaiwanStockKBar`），但免費 register 方案回傳 HTTP 400「請升級付費
Sponsor 方案」。要不要付費升級以取得真正盤中序列資料（可以做精確的
盤中即時停損、盤中最高低點先後順序判斷等），是留給使用者自己決定的
產品/預算問題。

### 6.3 日曆效應總覽（`analyze_calendar_effects_from_db.py`）
- 節前最後一天的隔日（跨假期）報酬率平均 **-0.51%，t 值接近 -10**——
  效應量僅次於 6.1 節的跳空規律，但做成風控疊加層後實測是負面的（見 4.5）。
  星期幾效應、月中位置效應也有掃描但效應量遠小於上述兩者，未列入
  可執行候選。

## 8. 現況結論與後續方向

- **目前唯一「站得住腳、可以考慮實際使用」的策略是 C**（結構轉折+量能確認，
  Sharpe 0.43），且已經過充分的參數/風控/混合測試，沒有找到能穩健推高
  Sharpe 到 1.0 的方法。
- **第 5 節的同日跳空回補策略是唯一新驗證出、扣完成本仍正 EV 的邊際策略**，
  但規模太小不適合單獨使用，下一步若要繼續深挖，建議測試把它當獨立小額
  sleeve 疊加到 C 上（尚未做）。
- 多個「統計上顯著但實務上失敗」的案例（短期反轉、延遲跳空訊號）都指向
  同一個台股量化的根本限制：**日線頻率下許多真實存在的規律，強度都不足以
  覆蓋約 0.6% 的來回交易成本**，這可能是這個資料頻率/資產類別下更普遍的
  現象，而不是個別策略設計的問題。
