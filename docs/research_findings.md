# 台股量化策略研究彙整

> 這份文件彙整「用真實資料尋找正 EV、風險調整後報酬夠好的台股交易策略」
> 這條研究線目前為止的所有結果——包含成功、失敗、被否證的假設，誠實記錄，
> 不只放好看的數字。每一項結論都是實際跑在 Neon Postgres 真實資料（透過
> FinMind 每日累積、經 GitHub Actions 執行回測）上的結果，不是模擬或預測。

最後更新：2026-09-18（配對交易/均值回歸/PEAD 月營收漂移驗證完成）

---

## 1. 資料與方法論

- **資料來源**：FinMind API → 每日 GitHub Actions 排程 → Neon Postgres。
  截至本次回測，資料庫已累積 **150 檔股票、2023-09-18 ~ 2026-09-17**（約 3 年）
  的日線 OHLCV。
- **為什麼所有分析都在 GitHub Actions 跑**：沙盒本身連不到 FinMind / Neon，
  所有「真實資料」的結果都是先寫腳本、commit、觸發 workflow、讀 GitHub
  Actions 的 job log 才拿到的——**絕不在讀到真實 log 之前預測或編造結果**。
- **反未來函數紀律**：所有訊號一律只用 T-1（含）以前已知的資料
  （`indicators.shift_by_group`），例外只有「訊號當天（T 日）自己的收盤價/
  成交量」這種在 T 日收盤後就已知、當天判斷當天用的特徵，符合
  `tw_quant/signals.py` 既有慣例。
- **交易成本**：全程套用 `tw_quant/costs.py` 的完整成本模型（證交稅、手續費、
  跳動點滑價），沒有任何「毛報酬」數字被當成能用的結果。
- **統計驗證方法**：
  - **Rank IC**：訊號與 forward 報酬做橫斷面 Spearman 等級相關，逐日算、
    取平均，t 值 = mean_IC / (std_IC / sqrt(n))（注意：沒做 Newey-West
    修正，重疊窗口的自相關會讓 t 值某種程度上偏高估）。
  - **高原 vs 尖峰檢查**：任何好看的單一回測數字，一定會在鄰近參數值上
    重跑，確認結果是「平滑高原」還是「一碰就崩的懸崖」——後者視為過擬合
    /巧合，不採用。C+D 混合策略的 Sharpe 0.60 就是這樣被抓到是假訊號的
    （見第 4.5 節）。
  - **EV / 勝率 / 風報比 / PF 的正確記帳**：backtest 結束時還沒平倉的部位，
    一定要用最後收盤價「虛擬平倉」後併入統計，否則會系統性低估 EV/勝率
    （贏家部位通常留倉最久，排除它們等於只看「已經出場的輸家」）。這個
    邏輯統一寫在 `tw_quant/backtest_stats.py`。

## 3. 目前最佳單一策略：結構轉折 C（Market Structure Shift + 量能確認）

這是整個研究過程中找到的**最站得住腳的候選策略**，多次重跑結果一致：

**訊號邏輯**：
- 魚池：流動性門檻 + 站上 60 日均線多頭排列（`signals.build_pool_mask`）
- 下跌情境確認：過去 20 日低點持續創新低（`dt_win=20`）
- 結構突破：收盤價突破過去 15 日高點（`swing_window=15`）
- 量能確認：成交量 > 20 日均量 × 1.3 倍（`volume_confirm_mult=1.3`）
- 出場：2.5×ATR 吊燈停利（`atr_multiplier=2.5`, `chandelier_lookback=10`）
- 大盤環境門檻放寬：`breadth_threshold=0.25`、`volume_ratio_threshold=0.9`
- 全域風控：產業曝險上限放寬到 30%（`max_industry_exposure_pct=0.30`）

**績效（約 3 年、完整交易成本）**：

| 指標 | 數值 |
|---|---|
| 總報酬 | 11.37% |
| CAGR | 3.79% |
| MDD | 11.69% |
| **Sharpe** | **0.43** |
| Calmar | 0.32 |
| 交易筆數 | 42 |
| 勝率 | 31.0% |
| EV%（勝率加權） | 1.53% |
| 獲利因子 PF | 1.36 |

**誠實評估**：使用者要求「持續探討直到 Sharpe 及格的 1.0」，但在系統性測試
過參數調整、風控放寬、訊號混合（共用資金池與獨立資金 sleeve 兩種方式都
試過）之後，沒有找到任何能穩健推高 Sharpe 到 1.0 的槓桿。已明確告知使用者：
在只有 3 年單一區間、沒有真正樣本外驗證的情況下，Sharpe 1.0 可能是不切實際
的目標。

## 4. 被否證/失敗的方向（誠實記錄）

### 4.1 短期反轉策略
IC 掃描顯示短期反轉有統計上顯著的訊號，但做成真正逐日調倉策略、套用完整
成本後，報酬轉負——訊號強度不足以覆蓋台股約 0.6% 的來回交易成本。

### 4.2 C + D（結構轉折 + 均值回歸）共用資金池混合
表面上 Sharpe 從 0.43 提升到 0.60，但做「高原 vs 尖峰」穩健性檢查時，
只要微調 D 策略的 `near_low_win` 參數（5→10→15→20），Sharpe 就從
0.60 崩到 0.13→-0.40→-0.91——是**懸崖不是高原**，判定為共用風控鎖耦合出
的過擬合假訊號，不是真正的分散化效果。

### 4.3 C + D 獨立資金 sleeve 混合
改用獨立資金池（不共用全域風控鎖，兩條權益曲線事後相加）重測，結果變得
平滑（不再是斷崖），但依然全面劣於 C 單獨使用（最佳組合 Sharpe 0.23，
仍低於 C 的 0.43）。

### 4.4 C + E（結構轉折 + 因子動能）跨引擎混合
與 C 單獨使用在統計上無法區分（0.42 vs 0.43）。

**結論**：分散化只有在兩條腿「各自夠強、且真正低相關」時才有效，光是
「低相關」本身不足以帶來穩健的 Sharpe 提升。

### 4.5 長假風控疊加層
假設：長假前最後一天的前一交易日收盤強制平倉，能不能降低風險、改善
風險調整後報酬？結果：MDD 確實從 11.69% 降到 9.46%，但總報酬從 11.37%
崩到只剩 0.71%（傷得更重），Sharpe/Calmar 雙雙惡化（0.43→0.07、
0.32→0.03）。診斷：這是個對 42 筆已精心篩選過的交易硬套的粗糙規則，
很可能打斷了好幾筆策略本身最好的趨勢延續型獲利單，母體層級的日曆效應
不會等比例轉移到這個特定的交易選股上。

### 4.6 延遲一天可執行版跳空訊號
背景：「T 日開盤跳空 → T 日盤中報酬」IC 高達 mean=-0.25、t=-54.82，是
全專案最強的統計規律，但原本的逐日引擎架構（T 日收盤算訊號、T+1 日開盤
才進場）天生無法交易「同一天」的效應。這裡改測「延遲一天」的可執行版：
用 T 日收盤已知的跳空幅度/盤中報酬當訊號，T+1 日開盤進場。IC 掃描顯示
延遲後訊號依然統計顯著（`intraday_ret` t=-4.9~-7.7，`gap_pct` t=-1.45~
-3.75），但套用完整成本後跑過的 36 組組合全部淨負（最佳 Sharpe 只有
-0.02，全部 PF < 1）——延遲一天後訊號還在，但強度已經扛不住交易成本，
跟 4.1 的短期反轉是同一種失敗模式。

## 5. 同日「開盤買、收盤賣」跳空回補策略（本次新增，唯一被驗證有效的邊際策略）

### 5.1 動機與架構突破

4.6 節確認了「同一天內」的跳空回補效應無法在延遲一天的架構裡使用。
使用者指出一個關鍵修正：日線 OHLC 本身就同時記錄了「當天開盤價」與
「當天收盤價」——不需要分鐘/tick 級盤中資料，只要是「T 日開盤觀察到
跳空、T 日收盤前決定出不出場」這種只用頭尾兩個價位的策略，用現有日線
資料就能正確回測。這個修正是對的，於是新建了專門的**當沖回測引擎**
`tw_quant/intraday_roundtrip.py`：T 日開盤看到跳空幅度夠大就買進、T 日
收盤全部平倉，訊號與執行都在同一天內完成，不依賴任何未來資訊。

**誠實揭露的三個限制**（寫在該檔案檔頭）：
1. 沒有台股現股當沖資格清單（信用交易資格、注意股/處置股排除等），
   假設候選股都能當沖，實際可交易標的可能比回測顯示的少。
2. 進場價用當天開盤價，假設能在開盤時或極短時間內成交，沒有額外開盤
   滑價（沿用系統慣例：進場只收手續費、不額外算滑價）。
3. 證交稅沿用系統一貫的標準 0.3% 賣出稅率，沒有假設當沖優惠稅率
   （歷史上台灣曾階段性調降當沖證交稅到 0.15%，但現況未確認，保守不
   假設適用——如果實際稅率更低，真實報酬會比這裡回測出來的更好）。

### 5.2 開發過程的插曲：一個看似是 dtype bug、實際是資金配置 bug

引擎第一版用 `.replace([inf, -inf], pd.NA)` 處理跳空幅度的除以零情況，
這會把 float64 欄位隱性升級成 object dtype，破壞後續數值篩選——已修正為
`np.nan`。但修正後測試仍然失敗（`top_n=1` 情境下永遠 0 筆交易），逐層
加印診斷後找到真正原因：**`top_n=1` 會讓 `per_stock_budget` 等於 100%
資金**，用整股（lot）無條件捨去後幾乎不留現金餘裕支付手續費，於是唯一
的候選交易被「現金不足」規則正確地拒絕了——這不是 bug，是這個極端測試
情境（把 100% 資金押一檔股票、零緩衝）觸發到的合理行為，跟
`factor_backtest.py` 既有的資金配置慣例一致。真實回測的 `top_n` 通常是
15~30，每檔只佔一小部分資金，lot 捨去自然會留下餘裕，不會遇到這個問題。
最終修法：測試裡小幅加碼可用資金留手續費緩衝，不動生產程式碼邏輯。

**誠實評估**：假設成立——大跳空（≥7%）確實有正 EV 的同日回補效應，且

好看很大一部分是因為分母（波動度）也極小，不是因為賺得多。**不建議單獨
使用**，比較有意義的下一步是把它當成小規模獨立資金 sleeve 疊加到策略 C
上（尚未測試）。

## 6. 對照學術文獻的四個經典短線策略（配對交易/均值回歸/PEAD）

使用者提供兩份 Gemini 研究對話，整理出學術與機構實務上有實證基礎的四種
短線策略（PEAD、配對交易、短期均值回歸、跨期動能），逐一對照本專案現有
發現、能測的都用真實資料測過。跨期動能已經被策略 C 跟因子動能引擎（E）
涵蓋過，不算新方向；以下是新測的三種。

### 6.1 統計套利/配對交易（Pairs Trading）——否證

新建 `tw_quant/pairs_trading.py`：同產業股票用 Engle-Granger 共整合檢定
（statsmodels）篩配對、每季（63 個交易日）重新選一次，價差 z-score 進出場
（entry_z 超過門檻進場、回到 exit_z 內或超過 stop_z 停損、最長持有 20 個
交易日），金額中性的多空雙腿，成本模型沿用系統既有的證交稅/手續費（放空
只算到公開的證交稅，**沒有算融券/借券費**，真實報酬可能更差）。

開發過程抓到一個真正的資料品質 bug：真實資料裡有 22 檔股票在形成窗格內
某些日子價格是 0（不是 NaN，可能是缺資料被記成 0），沒濾掉的話
`log(0)=-inf` 會讓共整合迴歸的避險比例算成 NaN，而且被汙染的迴歸算出來
的 p-value 還可能因為數值不穩定而異常地小，讓這種壞資料的配對反而排到
最前面、擠掉所有真正合理的配對——修好前 9 組參數組合真的是 0 筆交易，
修好之後（`_find_pairs` 排除形成窗格內出現過非正值的股票）才跑得出
真正的結果：

| formation_window | entry_z | 總報酬 | CAGR | MDD | Sharpe | Calmar | 交易數(含兩腿) |
|---|---|---|---|---|---|---|---|
| 252 | 2.0 | -11.61% | -4.18% | 11.94% | -0.73 | -0.35 | 394 |
| 252 | 2.5 | -6.83% | -2.42% | 7.27% | -0.91 | -0.33 | 224 |
| 180 | 2.5 | -14.56% | -5.29% | 14.71% | -0.94 | -0.36 | 230 |
| 120 | 1.5 | -43.66% | -17.99% | 43.97% | -2.04 | -0.41 | 814 |

9 組全部虧損，且門檻越低（交易越頻繁）虧得越慘——跟先前的短期反轉、
延遲跳空訊號同一種失敗模式：真實統計套利需要的執行速度/融券成本優勢，
散戶等級的交易成本結構完全負擔不起。

### 6.2 短期均值回歸（RSI 超賣 / 布林通道乖離）——否證，但過程中抓到一個重要的架構相容性 bug

第一版直接把 RSI 超賣、布林通道下軌訊號接到 `tw_quant/backtest.py` 的
逐日事件引擎（`entry_signal_fn`），結果 9 組參數組合全部 0 筆交易。追查
發現不是訊號太少見，而是**架構不相容**：那個引擎的吊燈停利公式用「過去
10 日高點 - 2.5xATR」當初始停損，是為「進場點貼近近期高點」的突破式
策略設計的；均值回歸策略的進場點剛好相反（貼近近期低點），算出來的
停損價常常高於進場價，被「停損價不低於進場價」的規則直接擋掉——實測
215/235 筆拒單都是這個原因。

解法（也是 `scripts/explore_reversal_strategy_from_db.py` 測前一輪短期
反轉訊號時已經用過的解法）：改用 `tw_quant/factor_backtest.py` 的定期
調倉引擎（排名+固定持有期，不做逐筆停損），把 RSI/布林通道 z-score 當
連續排名分數，買最超賣的股票：

| 訊號 | 持有天數 | top_n | 總報酬 | Sharpe | Calmar | 交易數 | 勝率 |
|---|---|---|---|---|---|---|---|
| RSI | 21 | 30 | 20.77% | 0.41 | 0.22 | 166 | 31.3% |
| BB_zscore | 21 | 30 | 16.99% | 0.36 | 0.19 | 160 | 31.2% |
| RSI | 21 | 20 | 4.80% | 0.18 | 0.05 | 172 | 33.1% |

36 組合中只有 5 組（13.9%）總報酬為正，且全部集中在最長的持有期（21個
交易日 ≈ 1個月）；持有期一旦縮短到「真正的短線」（3~10天），Sharpe 全面
轉負且越短越差（3天持有 Sharpe 低到 -0.53）。最佳組合的 MDD 高達 30%，
Calmar 只有 0.22，明顯劣於基準策略 C（Calmar 0.32）。結論跟短期反轉一致：
均值回歸效應存在，但只有在拉長到接近「波段」的持有期才勉強維持正值，
真正的「短線」均值回歸吃不過交易成本。

### 6.3 PEAD 月營收意外漂移——本輪唯一表現亮眼的新策略

用 FinMind 的 `TaiwanStockMonthRevenue`（月營收）當財報驚喜的代理指標，
因為沒有分析師共識預期資料：訊號 = 當月營收年增率 - 近 6 個月平均年增率
（用「意外程度」而不是單純營收成長，比較貼近 PEAD 原始定義的「超乎預期」）。

反未來函數是這個策略最關鍵的部分：FinMind 的 `date` 欄位是「營收所屬
月份」、不是公告日期，台灣法規要求次月 10 日內公告，這裡保守假設次月
15 號才算公開已知（多留 5 天緩衝），用 `merge_asof` 對齊進每個交易日、
再 shift(1) 天，比照 `factor_backtest.py` signal_fn「回傳值須為 T-1 已知」
的慣例。因為只抓月營收（沒抓季報），資料庫需要新增 `month_revenue` 表格
（SQLite + Postgres 都有），`ingest_daily_data.py` 也跟著擴充去抓這個
dataset。

用因子式定期調倉引擎（買意外程度排名最高的股票）測出來的結果：

| 調倉週期(交易日) | top_n | 總報酬 | CAGR | MDD | Sharpe | Calmar | 交易數 | 勝率 | PF |
|---|---|---|---|---|---|---|---|---|---|
| 63（約一季） | 20 | 26.23% | 8.38% | 26.55% | **0.48** | 0.32 | 42 | 31.0% | 1.73 |
| 63 | 30 | 25.95% | 8.30% | 26.13% | 0.48 | 0.32 | 44 | 29.5% | 1.71 |
| 42（約兩個月） | 20 | 19.71% | 6.42% | 26.53% | 0.38 | 0.24 | 68 | 27.9% | 1.49 |
| 21（約一個月） | 10 | 10.26% | 3.44% | 23.17% | 0.26 | 0.15 | 95 | 33.7% | 1.18 |

**9 組參數組合全部總報酬為正（100%）**，是目前為止測過的所有新策略裡
唯一達到這個一致性的。最佳組合的 Sharpe（0.48）甚至略高於基準策略 C
（0.43），且清楚的模式是「調倉週期越長（越接近 PEAD 原始文獻講的『數週』
時間尺度）表現越好」——跟 6.1/6.2 節「短線版本吃不過成本、拉長才活得下來」
是同一個道理，但這次連最短的週期（21天）都還是正的，效應本身看起來比
配對交易/均值回歸紮實。

**誠實的保留**：MDD 高達 26%，遠高於策略 C 的 11.69%，Calmar（0.32）
跟 C 打平，不是全面勝出；只有 141/150 檔股票有月營收資料可用（部分股票
可能是月營收資料不齊全或近期才上市）；這個結果只涵蓋約 3 年、單一區間，
沒有真正的樣本外驗證。如果要更進一步，這是本輪目前最值得繼續深挖的方向。

### 6.4 月營收動能 + 價量突破組合策略——訊號被系統既有風控結構性擋住，不是訊號沒用

第二份使用者提供的 Gemini 文件給出更具體的散戶版 PEAD 策略：月營收
YoY>15%或創12個月新高，加上價格突破20日高點+成交量爆量2倍確認，用
系統既有的逐日事件引擎測（這次進場點貼近突破新高，跟吊燈停利公式的
假設相容，不會重現 6.2 節那個 bug）。

真實資料上 18 組參數組合全部 0 筆交易，但這次追查後不是 bug：診斷顯示
魚池+營收動能+價量突破+大盤綠燈全部成立的候選有 56 筆（3 年裡不算
特別罕見），但**這 56 筆全部被系統既有的「單一產業曝險上限 10%」全域
風控擋掉**，一筆都沒有真正成交。原因是營收成長+價量突破這組條件很容易
在同一個產業裡「群聚」發生（景氣循環股常常整個類股一起噴），而 2% 固定
風險的部位規模模型算出來的單筆部位金額，對這些股票來說已經逼近或超過
10% 產業曝險上限。這是這組訊號的產業群聚特性跟系統既有全域風控（所有
策略共用的機制）交互作用的結果，不代表訊號本身沒有 edge——想看訊號
本身表現如何，需要另外放寬或關掉產業曝險上限重測（這裡沒有做，因為
會失去跟其他策略之間可比較的統一風控基準）。

文件裡的毛利率/營益率 QoQ 成長濾網、跟台股處置股/當沖占比法規防禦，
現有資料完全無法測試（沒有季報財報、沒有注意股名單），誠實列在腳本檔頭
而不是假裝做得到。股本濾網後來在 6.5 節補上了真實資料。

### 6.5 股本大小對策略表現的影響——結果跟文件論點相反，且發現 universe 本身的一個誤解

使用者問「文件講的中小型股比較有優勢，這部分有測到嗎」，答案原本是沒有，
而且一開始誤判了現有 150 檔 universe 的組成：`generate_stock_universe.py`
是依股票代號排序取前 150 檔，一開始以為台股代號小的（1000~1999 號段）
一定是股本大的老牌傳產股，但實際接上真實股本資料後發現**這個判斷是錯的**
——140 檔有股本資料的股票裡，中位數股本只有 17.9 億，有 108 檔（77%）
其實符合文件「股本 < 50 億」的門檻，universe 並不是想像中的大型股集中營，
只是這 150 檔本身沒有刻意涵蓋真正極端的中小型/冷門股（最大股本到 793 億）。

股本資料來源：FinMind 的 `TaiwanStockShareholding`（原本是外資持股比例
統計用的 dataset，已發行股數只是附帶欄位），股本（億元）= 已發行股數 *
10（面額新台幣 10 元的假設）/ 1 億，用每檔股票資料庫裡最早一筆讀數代表
「回測期間開始時的股本」。把 150 檔依股本中位數切成兩半，同一個策略
分別在兩半上跑：

**PEAD 月營收漂移**（用 `factor_backtest.py`，不受風控全域鎖影響，是
乾淨的對照）：

| 分組 | 檔數 | 股本範圍(億) | 總報酬 | Sharpe | MDD | 交易數 |
|---|---|---|---|---|---|---|
| 全部150檔 | 150 | — | 26.23% | 0.48 | 26.55% | 42 |
| 小股本組 | 70 | 3.2~17.7 | -3.16% | 0.06 | 35.60% | **4** |
| 大股本組 | 70 | 18.1~793.1 | 33.28% | **0.54** | 25.82% | 37 |

結果跟文件的核心論點**相反**：策略幾乎所有的邊際（37/42 筆交易、全部
正報酬）都來自股本相對較大的那一半，股本較小的那一半 3 年裡只觸發
4 筆交易、報酬轉負。策略 C（`backtest.py` 逐日引擎）也分開跑了，但
兩組股本結果都是負的（Sharpe -0.55 / -0.69），這裡誠實揭露一個方法論
上的干擾因子：策略 C 的「大盤環境判定」（regime breadth 指標）是用
「傳進去的 universe 裡有多少比例站上均線」算的，把 universe 切成兩半
之後，這個判定會分別在不同的 70 檔子集上重新計算，等於連帶換了一個不同
的大盤燈號依據，不是單純「同一個策略、只換股票池」的乾淨切分，所以策略
C 這組數字不採信、只列 PEAD 的結果。

**誠實的整體結論**：至少在我們現有的（本身就不是真正中小型股集中的）
樣本裡，沒有找到「股本越小、edge 越大」的證據，反而觀察到相反的方向；
但小股本組只有 4 筆交易，樣本小到不能當成有力的反證，比較準確的說法是
「沒有支持文件論點的證據」而不是「證明文件論點是錯的」。要真正驗證這個
假設，需要重新設計 universe 選股（納入真正的中小型/冷門股，而不是現有
這種依代號排序的取樣方式），這裡沒有做，是刻意的範圍限制。

## 7. 其他重要發現

### 7.1 全專案最強統計規律：隔夜跳空 → 當日盤中報酬
`analyze_calendar_effects_from_db.py` 發現「T 日開盤跳空幅度」與「T 日
盤中報酬（收盤 vs 開盤）」呈現極強負相關：**mean IC = -0.25，t = -54.82
（n=728 天）**，是整個探索過程效應量最大、統計上最穩健的規律。第 5 節的
同日回補引擎就是為了把這個訊號變成可執行策略而建的。

### 7.2 FinMind 盤中資料現況
確認 FinMind 有提供分鐘級/tick 級歷史資料（`TaiwanStockPriceTick`、
`TaiwanStockKBar`），但免費 register 方案回傳 HTTP 400「請升級付費
Sponsor 方案」。要不要付費升級以取得真正盤中序列資料（可以做精確的
盤中即時停損、盤中最高低點先後順序判斷等），是留給使用者自己決定的
產品/預算問題。

### 7.3 日曆效應總覽（`analyze_calendar_effects_from_db.py`）
- 節前最後一天的隔日（跨假期）報酬率平均 **-0.51%，t 值接近 -10**——
  效應量僅次於 7.1 節的跳空規律，但做成風控疊加層後實測是負面的（見 4.5）。
  星期幾效應、月中位置效應也有掃描但效應量遠小於上述兩者，未列入
  可執行候選。

## 9. 現況結論與後續方向

- **目前唯一「站得住腳、可以考慮實際使用」的策略是 C**（結構轉折+量能確認，
  Sharpe 0.43），且已經過充分的參數/風控/混合測試，沒有找到能穩健推高
  Sharpe 到 1.0 的方法。
- **6.3 節的月營收 PEAD 漂移策略是本輪表現最亮眼的新發現**：9 組參數
  100% 正報酬，最佳 Sharpe 0.48 略勝策略 C，但 MDD（26%）遠高於 C
  （11.69%），Calmar 打平，且只有 3 年單一區間的結果，值得列為下一輪
  優先深挖的方向（比如跟 C 做獨立資金 sleeve 混合）。
- 配對交易、RSI/布林通道均值回歸（6.1/6.2 節）用真實資料重新驗證後雙雙
  否證，符合「短線版本吃不過交易成本、只有拉長到波段尺度才勉強打平」的
  一貫模式；營收動能+價量突破組合（6.4 節）訊號本身無法判斷有沒有 edge，
  因為被既有的產業曝險全域風控結構性擋住，是本輪唯一一個「查不出訊號
  好壞、只查出被風控擋住」的未竟結果。
- **6.5 節測了「中小型股比較有優勢」這個文件核心論點，結果是相反的**：
  PEAD 策略幾乎所有邊際都來自股本較大的那一半（Sharpe 0.54 vs 全部
  150 檔的 0.48），股本較小的那一半 3 年只有 4 筆交易、報酬轉負——但
  這個樣本本身不是真正的中小型股（現有 universe 是依股票代號排序取樣，
  沒有刻意涵蓋極端小型/冷門股），且小股本組樣本數太少，只能說「沒有
  支持文件論點的證據」，不能說「證明是錯的」。過程中也意外發現先前對
  universe 組成的判斷是錯的：150 檔裡有 77% 股本其實 <= 50 億（文件的
  中小型股門檻），不是原本以為的清一色大型老牌股。
- **5 節的同日跳空回補策略仍是唯一驗證出、扣完成本仍正 EV 的邊際策略**，
  但規模太小不適合單獨使用，下一步若要繼續深挖，建議測試把它當獨立小額
  sleeve 疊加到 C 上（尚未做）。
- 多個「統計上顯著但實務上失敗」的案例（短期反轉、延遲跳空訊號）都指向
  同一個台股量化的根本限制：**日線頻率下許多真實存在的規律，強度都不足以
  覆蓋約 0.6% 的來回交易成本**，這可能是這個資料頻率/資產類別下更普遍的
  現象，而不是個別策略設計的問題。
